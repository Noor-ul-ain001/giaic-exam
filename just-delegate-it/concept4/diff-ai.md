# Concept 11: Same Job, Different AI

---

## The Core Idea

You have written a brief.
**The test of a brief is that it works somewhere else.**

A brief that only works in one tool is not a brief — it is a script for that tool.

---

## Do It Now

**Step 1:** Open a second free assistant you have not used in this course.

> If you only have one assistant — open a fresh chat in the same one and treat it as the second run.

**Step 2:** Paste your complete running brief — **unchanged.**

**Step 3:** Record five things for this run only:

| What to Record | Question to Answer |
|----------------|-------------------|
| **Completion** | Did it finish the job? |
| **Messages needed** | How many messages did it take? |
| **Authority** | Did it honor the Authority line? |
| **Caveats** | Did it mark anything `unverified`? |
| **Deliverable** | How did the result compare to your first run? |

> If you ran it in the same assistant with a different model — write down which test you ran. That tests **run-to-run variation**, not portability.

---

## What Just Changed?

### Why the Brief Traveled

> The brief traveled because it **describes the job — not the tool.**

Nothing in your six lines names a button.

```
Button names   →  differ between assistants
Button names   →  change every few months
The discipline →  does not change
```

| What Changes | What Stays |
|-------------|-----------|
| Where the web search switch is | The need for current information |
| What the model is called | The six lines of the brief |
| How files are attached | The instruction to stay inside the source |
| Which plan includes scheduling | The standing instruction you wrote once |

> Where each control lives is a page you look up — the **Quick Reference.**
> Not a thing you memorize.

---

## What You Recorded — And What It Is Not

> What you wrote down is a **record of two runs on one day.**
> It is **not a ranking** of two assistants.

Models change too fast for a ranking made today to be true next month.
This course never asks you to make one.

> For choosing an assistant for real work — see:
> **Which AI Employees in 2026** — the page that stays current.

---

## What to Notice

After both runs, ask:

- Did the brief need **any change** to run in the second assistant?
  - If yes — which line? Was it a **brief problem** or an **assistant problem?**
- Where did the two results differ — in the **facts**, the **form**, or only in the **buttons?**
- Which line of the brief did the second assistant **handle worst?**

---

## Verify Before You Accept

Trace **one claim** in the second result — the same four steps as Concept 10:

```
Identify → Trace → Challenge → Decide
```

Then decide: **Accept, Correct, Investigate, or Reject.**

> The method did not change when the assistant did.
> The standard travels with the brief.

---

## Your Turn

Write both runs into your **Delegation Record** — side by side — as observations about this run.

```
Not: "Assistant A was better than Assistant B."
But: "Assistant A marked two items unverified. Assistant B marked none.
      I opened one link from each. Assistant B's unmarked claim was wrong."
```

> Observations about the run.
> Not a verdict about the assistant.

## The Full Course — Eleven Concepts, One Line Each

| # | The One Line |
|---|-------------|
| **1** | Asking keeps the work with you. Giving AI the job leaves you the checking. |
| **2** | Say what should exist when the job is done. Leave the clicks to the machine. |
| **3** | A brief is six questions you answer before AI starts: outcome, context, constraints, authority, deliverable, verification. |
| **4** | When the job needs what is true today, make AI look — and check that it looked. |
| **5** | Give AI the source, tell it to stay inside it, and check that it did. |
| **6** | Name the thing you want to hold at the end. Check that the caveats survived the trip. |
| **7** | Say what AI may decide alone and what it must ask about. Ask for the plan first. |
| **8** | The second time a job comes back, save what does not change. The third time, put it where AI reads by itself. |
| **9** | The smallest message that fixes it is the intervention. Then write the lesson into the brief. |
| **10** | Identify, trace, challenge, decide. AI doing the work does not transfer accountability to AI. |
| **11** | The job belongs to you. The model is replaceable. |

## The Two Things Under All Eleven

### One Rhythm
```
Define → Delegate → Observe → Intervene → Verify → Accept
```

### One Rule for the Screen
```
Need first — then tool.
A control is learned when a job needs it, not before.
```
