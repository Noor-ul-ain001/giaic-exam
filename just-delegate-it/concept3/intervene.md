# Concept 9: Intervene When AI Goes Wrong

---

## The Core Idea

Every job so far mostly worked.
This one you **break on purpose** — so that the move that fixes it is yours before you need it.

---

## Do It Now

**Step 1:** Open a fresh chat.

**Step 2:** Run your running brief with **two lines deleted:**
- Constraints
- Authority

**Step 3:** Watch where it drifts:
- Paid courses appearing
- Wrong language
- Wrong level
- A decision you did not delegate

**Step 4:** Fix it with the **smallest message you can write.**

---

## The Six Intervention Moves

The symptom tells you which move to use:

| What You See | The Move | What You Do |
|-------------|----------|-------------|
| It answered a different question | **Stop** | Restate the outcome in one line |
| One fact or one line is wrong | **Correct** | Name the error and what should replace it |
| It is heading the wrong way but is not wrong yet | **Redirect** | Name the direction — not the whole job again |
| The job itself was wrong | **Change** | Change the requirement and say that you changed it |
| It cannot do a step at the level the job needs | **Escalate** | Turn on a stronger model and run the same brief again |
| It keeps failing after escalation | **Take it back** | Some jobs are yours |

---

## The Move People Miss: Escalate

Most people only know two moves — correct or rewrite.
**Escalate** is the one that gets missed.

```
Fast model   →  good for simple, quick jobs
Slower model →  better for multi-step, careful comparison, calculation
Strongest    →  must be right, no room for error
```

**How to escalate:**

1. Move to a stronger model or thinking mode
2. Run the **same brief again** — unchanged
3. If the stronger model is not on your plan — make the job smaller: one step at a time, each one checked

> What the settings are called changes with every release.
> The **names** live in the Quick Reference.
> The **rule** does not change:

```
Sometimes "AI failed" means "I used the wrong level."
```

## Observe and Intervene in Different Contexts

| Context | How It Works |
|---------|-------------|
| **In a chat** | Observe and Intervene are one act — you read the reply and answer it |
| **In a live agent** | They are separate — you watch it run and stopping it is a real button |

---

## What to Notice

After you break the brief and fix the drift, ask:

- Which of the six moves did you use — and was it **the smallest one that would work?**
- Did AI do what you asked — or just **say that it did?**

> `"I have corrected the table"` is a sentence.
> **Look at the table.**

- What line would have **prevented the drift?**
  - That line is a constraint you have now learned — write it in.

---

## Verify Before You Accept

Check the one thing you corrected — **in the result itself**, not in AI's description of the result.

```
AI says:  "I have fixed the price column."
You do:   Open the table. Check the price column.
```

> A claimed fix that did not happen is the failure this step exists to catch.

---

## Your Turn

**Step 1:** Write the line you learned into your running brief as a **Constraint** or **Authority** line.

**Example:**
```
Constraints: Only free courses. Do not include paid options,
             even if they have a free trial.
```

**Step 2:** Run the full brief in a fresh chat.

**Step 3:** Confirm the drift is gone.

---

## The Correction Formula

When you intervene, keep it short and structured:

```
1. What is wrong
2. Why it matters
3. Which direction to go
```

**Example:**
```
The table includes paid courses. This brief is for free options only.
Remove any course that requires payment to start.
```

> That is the whole message. Nothing more is needed.

- [ ] Did I check the fix **in the result itself** — not in AI's description?
- [ ] Did I write the **lesson into the brief** so it does not happen next time?

## The Running Brief — What It Now Contains

```
Concept 1  →  Outcome
Concept 2  →  Outcome + Constraints
Concept 3  →  All six lines
Concept 4  →  Constraints: current information required
Concept 5  →  Context: source added, stay-inside instruction
Concept 6  →  Deliverable: form named precisely, caveats protected
Concept 7  →  Authority: method veto + action boundaries
Concept 8  →  Brief saved outside chat, stable context in Project
Concept 9  →  Constraints + Authority hardened by what drift taught you
```

## The Intervention Loop

```
Drift spotted
     ↓
Smallest move that fixes it
     ↓
Check the result — not AI's claim about the result
     ↓
Write the lesson into the brief
     ↓
Run again — confirm drift is gone
```
